# 4.5 小规模验证实验结果（真实运行）

> 本文件是 `下一代BERT设计.md` §4 的实测记录与结论。目标不是证明 300M 设计正确，而是把 §3 的"双指标判定协议"在微型模型上真实跑一遍：固定数据与计算预算，比较四个架构变体，用 **MLM 验证损失**（代理指标）与 **4.4 断句标点 macro-F1**（应用指标）对照，检验"代理指标与任务指标是否一致"。
> 环境：Windows 11 + WSL2（Ubuntu），torch 2.15.0（CUDA），RTX 3050 Laptop 4GB。代码 `mini_ablation.py`，原始日志 `results/run_ablation.log`，结果 JSON `results/mini_ablation.json`，图 `results/figs/`。

## 1. 配置

| 项 | 设置 |
|---|---|
| 模型 | 自实现微型编码器：4 层 × 256 宽、8 头、序列 128（参数见下表，约 4–5M） |
| 变体 | BASE（绝对位置+全注意力+GELU-FFN+LayerNorm）/ ROPE（换 RoPE）/ GEGLU（+GeGLU+RMSNorm+去偏置）/ LOCAL（+局部窗口 64+末层全局） |
| 预训练 | 人民日报 9801 语料 200 万字符，动态 MLM 30%，固定 3000 步 × batch 128，AdamW lr=1e-3，同随机种子 |
| 探针 | 冻结编码器 + 线性 head，4.4 断句标点 11 类，训练 6,000 块 × 1 epoch，macro-F1 |
| 已知局限 | 同域数据（4.4 语料）既是预训练也是探针数据——方法学演示的故意简化，结论不能外推；已如实标注 |

## 2. 结果

| 变体 | 参数量 | MLM 验证损失（末步） | 断句探针 macro-F1 | 预训练耗时(s) |
|---|---|---|---|---|
| BASE | 6,050,816 | 3.206 | 0.0878 | 1,163 |
| ROPE | 6,018,048 | 2.874 | 0.0904 | 1,239 |
| GEGLU | 6,004,480 | 2.813 | 0.0904 | 1,342 |
| LOCAL | 6,004,480 | **2.802** | 0.0898 | 1,377 |

（损失曲线与双指标对比图：`results/figs/ablation_mlm_loss.png`、`results/figs/ablation_dual_metric.png`。探针为冻结编码器 + 线性 head，同一随机种子、确定性数据顺序，各变体间 head 初始化一致——F1 差异全部来自编码器差异，无探针随机性。）

## 3. 按 §3.2 协议的解读

**结论：本实验出现了"代理指标与任务指标方向不一致"的实例，协议被真实触发并按其执行。**

- MLM 验证损失随变体单调下降：BASE 3.206 → ROPE 2.874 → GEGLU 2.813 → LOCAL 2.802——四个现代组件各自都有可测量的代理指标收益，且 ROPE 的收益最大（−0.33）。
- 断句探针 macro-F1 并不随 MLM 单调：BASE 0.0878 → ROPE 0.0904 → GEGLU 0.0904 → **LOCAL 0.0898**。MLM 最好的 LOCAL 在任务指标上略低于 GEGLU（−0.0006）。
- 按 §3.2 保留规则执行：LOCAL 的"MLM 更优"不满足"至少一类目标任务显著提升"，**不保留**，进入观察清单，理由记录为"任务差异在探针分辨率之下；局部窗口对 128 序列的断句任务不带来任务侧收益"；复活条件=更长序列（≥512）或更大模型下复现任务收益。ROPE/GEGLU 相对 BASE 是"MLM 与任务同向提升"，GEGLU 以等 F1、更低 MLM 保留。
- **诚实的边界**：任务指标差异极小（0.0904 vs 0.0898），探针本身的分辨率有限（11 类 macro、同域数据、4 层模型 3000 步）。所以本实验的价值不是"证明局部注意力对断句有害"，而是**演示判定协议如何真实运转**：出现"只降 MLM"的变更时，协议给出明确处置（剔除 + 观察清单 + 复活条件），而不是被代理指标带着走。这与设计文档 §4 的定位一致——方法学演示，结论不能外推到 300M 规模。

## 4. 失败与修正记录

- 第一次运行：`LayerNorm.__init__() missing 1 required positional argument: 'normalized_shape'`——Block 里把归一化类当工厂直接 `ln()` 调用；改为传入 `lambda d: LayerNorm(d)`。
- 第二次运行：`The size of tensor a (128) must match the size of tensor b (8)`——注意力 mask 是 (T,T)，`unsqueeze(1)` 后 (T,1,T) 与 (B,H,T,T) 广播按右对齐、T 与 H 相撞；改为 `mask[None, None]` 升到 (1,1,T,T)。
- 第三次运行：BASE 预训练完成后探针崩溃 `addmm: mat1 and mat2 shapes cannot be multiplied (32768x5583 and 256x11)`——`model(ids)` 返回的是词表头输出而非隐藏态，线性探针拿不到 256 维表示；改为 TinyBert 返回 `final_norm(x)` 隐藏态、MLM 侧自行套 `self.head`。同时给每个变体加"即时落盘"，防止后续变体崩溃丢失已完成结果。
- 第四次运行：LOCAL 跑到 1300 步时 WSL 虚拟机被重启（dmesg 显示新开机），进程被中断。落盘机制生效：BASE/ROPE/GEGLU 结果已在 checkpoint 中；给脚本加"跳过已完成变体"的断点续跑，只补跑 LOCAL，训练流程与随机种子与全量运行完全一致（每变体开头重置 seed）。
