# 设计下一代 BERT："2026 版 ModernBERT"（约 3 亿参数 · 8K 上下文）

> 课程：大语言模型与应用实践（2026 秋）· L2 part2 第 90–91 张
> 设计约束（题目给定的讨论假设）：约 **3 亿参数**、**8K 上下文**，面向**中英文**分类、抽取、检索和重排。
> 本文按题目的三组问题组织：架构题（§1）、任务题（§2）、证据题（§3）；§4 是真实运行的小规模验证；§5 是与题目 Notes 的分歧点说明与自评。

---

## 0. 一句话方案与资源账本

**24 层 × 896 宽的 biasless 双向编码器：RoPE + 每 3 层 1 个全局注意层（其余局部窗口 128）+ GeGLU(8/3) + RMSNorm(pre-norm) + 64K BBPE 中英词表；以"动态 MLM + 连续片段恢复"为主目标，RTD 为对照分支，SimCSE 对比为末段分阶段分支。总参数约 2.9 亿（含词表）。**

账本按 L2 part2 第 225 张口径（2 FLOPs/乘加、共享输入输出权重只计一次）：

| 项目 | 取值 | 说明 |
|---|---|---|
| 层数 L / 宽度 d | 24 / 896 | — |
| 每层参数 | 12d² ≈ 9.63M | 注意力 4d² + FFN 8d²（GeGLU 扩展率 8/3 时 3·d·8d/3 = 8d²，与经典 4d FFN 参数量相同） |
| 块参数 N_block | 12Ld² ≈ 231M | — |
| 词表 V | 65,536（BBPE，byte fallback） | 决策见 §1.4 |
| 嵌入参数 | V·d ≈ 58.7M | 输入输出共享，只计一次 |
| 总参数 | ≈ **2.9 亿** | 231M + 58.7M + 归一化等小项 |
| 权重字节（bf16） | ≈ 580 MB | — |
| 训练 FLOPs（D=100B token） | 主项 6N_block·D ≈ 1.39e20 | 6ND 公式 |
| 8K 长上下文修正项 | 12L·D·s·d ≈ 2.11e20 | s=8192 时约为参数主项的 **1.5 倍**（s/(6d) ≈ 1.52）；若不用局部注意，注意力成本随 s² 增长，8K 目标不可承受 |
| 标准 KV 缓存（8K 序列，bf16） | ≈ 705 MB | L·s·2d·2B = 24·8192·1792·2 |

> 修正项 ≈ 1.5× 主项这一事实就是本设计的出发点：**8K 上下文的成本结构由注意力可见范围决定**，所以"局部/全局层比例"是我证据题的第一验证项（§3），而不是词表这类"锦上添花"的变量。

## 1. 架构题

### 1.1 默认配置（有公开证据支撑的部分）与必须先消融的清单

**默认配置**：

1. **RoPE 相对位置编码**，取代绝对位置嵌入。8K 需要外推能力；ModernBERT 已验证 RoPE 在双向编码器上的可行性与长上下文扩展收益（8192 token 训练范围）。
2. **交替局部/全局注意力**：每 3 层 1 个全局层（8 全局 + 16 局部），局部窗口 128 token。这是 ModernBERT 的核心成本设计，起点是"可复现基线"，不是定理。
3. **Biasless 线性层 + RMSNorm + pre-norm**。去偏置省参数且被 PaLM/ModernBERT 系验证无害；RMSNorm 与 LayerNorm 差异很小（ModernBERT 附录有对比），选 RMSNorm 主要因长序列下计算更省，作为 A5 的替代消融保留 LayerNorm。
4. **GeGLU 门控 FFN，扩展率 8/3**（与经典 FFN 同参数量）。SwiGLU 作为等价替代入消融——流行组件之间的差异可能很小，最终选择还应受实现效率影响。
5. **动态 MLM 为唯一默认预训练目标**（30% mask，80/10/10）；其余目标按 §2 的规则加入。
6. **dropout 0.05**（不完全去除：我的语料规模假设 100B token 级，不足以支撑 ModernBERT 式完全去 dropout）。
7. **不默认加入 MoE、GQA**：MoE 路由是否适配这些任务、GQA 是否适配编码器负载，都不能由其在其他模型中的流行程度决定；仅在容量或吞吐瓶颈出现时单独立项。

**必须先消融的清单**（证据最弱 × 影响最大）：

| # | 消融项 | 候选取值 | 理由 |
|---|---|---|---|
| A1 | 全局层频率 | 1/2、1/3、1/4、1/6 | 8K 训练成本的第一决定因素（§0 修正项） |
| A2 | 局部窗口 | 64 / 128 / 256 | "窗口变长，是否意味着远距离关系也真正学会"——长程证据探针直接检验 |
| A3 | 词表大小 | 48K / 64K / 96K | 中英压缩率 vs 每 token 计算成本的平衡（§1.4） |
| A4 | FFN/归一化组合 | GeGLU vs SwiGLU；RMSNorm vs LayerNorm | 同参数量下的容量与实现效率差异需要实测 |
| A5 | dropout | 0 / 0.05 / 0.1 | 与语料规模、训练时长的交互 |
| A6 | RoPE 基频/外推 | θ=1e4/1e5/1e6；NTK 缩放 | 8K 尾部位置质量没有现成答案 |

消融执行方式：全部在 100M 级小模型上先做（见 §4 的真实演示），主模型只复现胜出配置与 1–2 个关键结论。

### 1.2 保留 ModernBERT 的哪些设计

| ModernBERT 设计 | 采纳 | 理由 / 扬弃 |
|---|---|---|
| RoPE 取代绝对位置 | ✅ | 8K 外推是硬需求 |
| 交替局部/全局注意力（1/3） | ✅ 作起点，比例入消融 A1 | 长上下文成本结构 |
| Biasless + GeGLU | ✅ | 省参数、容量 |
| 动态 MLM、无 NSP | ✅ | 现代共识 |
| Unpadding + FlashAttention | ✅（属计算实现层，§1.5） | 训练吞吐第一杠杆 |
| 去 dropout | ⚠️ 保留 0.05（A5） | 我的预算假设不支持完全去除 |
| 局部窗口 128 | ⚠️ 入消融 A2 | 面向 8K 可考虑 256 |
| 词表 50,368（英文 BPE） | ❌ 换 64K 中英 BBPE | 题目要求中英；决策过程见 §1.4 |

**明确扬弃**：NSP/SOP 类目标；whole-word masking 在中文上的词典式实现；绝对位置嵌入。

### 1.3 归一化与门控前馈的决策

- **归一化**：RMSNorm + pre-norm（注意力与 FFN 之前），编码器出口一个 final norm。理由：pre-norm 训练稳定、降低 warmup 敏感性；RMSNorm 省 2/3 归一化计算，在 8K 长序列上非平凡。判定依据 A4：若 RMSNorm 在同等预算下不劣于 LayerNorm 即采用（实现简单、生态成熟是权重）。
- **门控 FFN**：GeGLU，扩展率 **8/3**（保持与经典 4d FFN 完全相同的参数量，公平比较）。决策依据：固定参数量时 gating 分支提升容量已被广泛验证；若 A4 显示增益不显著，回退 GELU-FFN（部署算子更成熟）。

### 1.4 词表决策（V=64K）

- **方法**：SentencePiece BBPE + byte fallback，语料按中文 60%（新闻、百科、社区）/ 英文 40%（books、wiki、少量 code）采样约 20–40GB 训练。
- **决策变量与判据**：先做切分长度、罕见符号覆盖、字节成本的统计，再定大小。判据是**下游任务 F1 与每 token FLOPs 的比值**，而不是 PPL（PPL 对词表大小有系统性偏差）。中文 2.1 万常用字在 48K 下基本每字 1 token，英文 token 数随词表减小而上升；96K 的边际压缩收益要额外付出 28M 参数（+10%）。预期甜点 64K，但 48K 若在下游无显著劣化就选 48K（省参数）。
- **中文粒度**：不引入词典分词。BBPE 在中文上退化为"字 + 高频二字词"混合，对四类任务足够；词典分词引入预处理脆弱性与 OOV 错误。古汉语/OCR 类噪音由数据侧扰动处理（§3.1 数据部分）。

### 1.5 预算有限：从头训练，还是继续适配？（模型结构与计算实现分开说明）

**模型结构**（算法层，与实现无关）：§0 的 24×896 配置 + §2 的目标安排。

**计算实现**（工程层，可按硬件替换）：FlashAttention-3 类内核 + Unpadding（变长 packing 去无效 padding）；bf16 AMP + fp32 主权重；局部层开梯度检查点；FSDP(ZeRO-3) + 可选张量并行；按长度分桶；推理侧编码器无自回归，KV 缓存只体现在长序列显存（§0），检索服务用 batch 化推理框架。

**训练起点的决策**——我把这个题拆成"前置检查 + 两条路线 + 翻转条件"：

- **前置检查（决定走哪条路的依据，而非偏好）**：(1) 候选底座（mmBERT/MrBERT 一类现代多语编码器）的中文覆盖统计——词表在中文新闻/百科上的未登录率与切分长度；(2) 其训练上下文长度与 8K 目标的差距及"改位置编码+长上下文继续训练"的适配成本；(3) 许可证与使用条件；(4) 其训练配方（数据配比、掩码策略）是否可迁移到我的消融结论。
- **首选路线：从 mmBERT/MrBERT 一类现代多语编码器继续预训练**（当检查通过时）。理由：预算有限是题目的显式假设；继续训练省掉 70–90% 的预训练算力；mmBERT 已展示多语采样与训练阶段安排（退火语言学习）的价值，MrBERT 展示词表/领域/维度适配的路径。
- **备选路线：从零训练**（当检查失败时）。失败条件：底座词表中文覆盖差（扩词表 = 重训嵌入 + 全模型重新预热）、上下文 <2K（改 8K 需改注意力拓扑，复用收益骤减）、许可证受限。此时复用 ModernBERT 式骨干与训练实现（开源、可复核），而不是复用权重。
- **关键纪律**：权重复用不是免费兼容。大幅更换词表、隐藏维数或注意力拓扑后，"继续训练"的真实成本应与"从零"显式比较，不能默认前者便宜。
- **两者共用的下游**：结构消融全部在 100M 小模型从零完成（各约 2e18 FLOPs，§4 为演示），结论用 μP 初始化迁移到主模型并抽查复现。

## 2. 任务题

### 2.1 四个训练目标分别补什么能力（及代价）

| 训练目标 | 补的能力 | 代价/风险 | 安排 |
|---|---|---|---|
| **动态 MLM**（每 batch 重采样 mask） | 数据利用率：同语料多轮遍历不重复同一 mask 组合；"同一文本不同缺损"下的表示稳定性 | 几乎为零 | **联合训练，可控基线** |
| **连续片段恢复**（掩码连续 span 并恢复） | 长距离语义整合与结构恢复：恢复连续片段必须综合跨句证据 → 直接对应 8K 长程目标；SpanBERT 已验证片段监督对抽取类任务的价值 | 目标工程复杂度中等；mask 比例需网格实验 | **联合训练**（15%/30%/40% 掩码率小规模网格，片段长度随训练递增） |
| **RTD 替换词检测**（ELECTRA/DeBERTaV3 式） | token 级细粒度监督：监督信号覆盖全部 token，同样算力下监督密度高数倍；对分类/抽取的细粒度特征有帮助 | 需要生成器（预算计入其训练与采样成本）；可能产生"替换过于容易/词频捷径" | **强对照分支，不是无条件叠加**：MLM 头兼任生成器、判别头共享主编码器（DeBERTaV3 梯度解耦共享），同预算下与 MLM 路线对照 |
| **SimCSE 式对比学习** | 句级表示对齐：拉近语义等价句、推远无关句 → 直接服务检索与重排 | 对比学习可能损伤 token 级能力（需要 MLM 回放或独立分支防遗忘）；无监督版必须保证两次编码真的得到不同 dropout 视图 | **分阶段分支**：预训练收尾 10% 步数 + 任务适配阶段；用可信语义正例与困难负例 |

**为什么不全联合**：四者作用于不同粒度（token/片段/句），SimCSE 的句级对齐与 MLM 的字面细节保留存在张力；"什么都能加"的组合让每项变化无法归因（这正是题目"避免什么都加"的警告）。所以每个目标都有明确的负责区域与退出条件。

### 2.2 联合 / 分阶段 / 分支的排期

```
阶段1（前 90% 步数，联合）：动态 MLM（主）+ 连续片段恢复（混合掩码）
         └ 共享主编码器，各自轻量 head；损失权重 0.7·L_mlm + 0.3·L_span
阶段1.5（对照分支，同预算另跑一条线）：RTD 线（MLM 头生成替换 + 判别头）
         └ 与阶段1 同数据同 FLOPs 对照，§3.2 判定谁留下
阶段2（末 10% 步数，分支）：SimCSE 对比分支（阶段1 目标保留 1/4 权重防遗忘）
阶段3（按任务适配）：向量检索 / 成对重排 接口各自微调（这是使用阶段，不是预训练目标）
```

- **RTD 的定位**：DeBERTaV3 的梯度解耦共享解决了生成器/判别器目标冲突，但它的收益不能与其他架构因素混为一谈。若 RTD 在分类/抽取上稳定优于 MLM 线且成本可接受，选它作为理解分支；不会为了"全面"同时保留所有损失。
- **SimCSE 的定位**：检索相关性 ≠ 语义相似 ≠ NLI，所以阶段 3 仍要加入与目标检索任务匹配的数据；若索引容量重要，再实验 Matryoshka 式多维表示（注意：截短只省索引与相似度计算，不省编码器前向）。

### 2.3 Text Diffusion：新增用途，还是理解任务的必要组件？

**结论：新增用途（按需建立的生成分支），不是理解任务的必要组件。**

1. 四类下游任务都是判别式理解，不需要生成整段文本；MDLM、LLaDA 证明了双向编码器 + 掩码扩散的生成路线值得研究，但**不能据此推断把扩散目标加入通用编码器必然提升分类、抽取和检索**。
2. 若应用确需受约束补全/编辑：从底座复制一个分支，补高掩码状态、加权目标与反向采样，单独画出"质量—迭代次数—延迟"曲线，并检验原理解能力是否保留。
3. 必要性判定标准（重开讨论的条件）：固定四任务评测上，加扩散联合训练相比不加有显著提升且部署成本可接受——目前无公开证据满足。

## 3. 证据题

### 3.1 优先验证的三项变化与完整基线

选择逻辑：**优先验证"直接对应 8K 硬约束与中英文任务、且能低成本归因"的变化**。

1. **V1：局部/全局层比例 + 局部窗口**（A1+A2）。8K 成本结构第一变量（§0：修正项 ≈1.5× 主项）；也是"窗口变长是否等于长程关系真学会"的直接检验。
2. **V2：训练目标组合**（动态 MLM vs +连续片段恢复 vs RTD 对照线）。对应"如何安排学习目标"；RTD 作为独立对照保留。
3. **V3：词表与中英数据配比**（48K/64K/96K × 中文比例 50%/60%/70% 的粗网格）。中英文任务效率的直接变量。

> 与题目 Notes 的分歧说明：Notes 建议三项为"领域和语言数据适配、掩码目标搭配、句向量/检索对比适配"。我把"检索对比适配"降级到阶段 2/3（它的作用对象是检索/重排两个任务，而题目还有分类/抽取，且它依赖 V1/V2 定稿后的底座），把"局部/全局比例"提前——因为 8K 是本题最硬的结构约束，在 8K 下它的成本权重超过任何训练目标。若预算进一步收紧，按 Notes 的顺序先做低成本归因（数据、掩码、检索三件套）也是合理的；这是一个预算序，不是观点冲突。

**固定基线**（所有比较的公共条件）：

- **数据**：固定混合语料采样（中文新闻/百科/社区 60% + 英文 books/wiki/code 40%），总量 20B token，去重、核对测试污染、保留真实文档边界；**长上下文样本必须包含真正需要远程信息的文档**，而不是把无关短句拼到 8K；打包时明确文档之间是否允许交互（主实验：同一 chunk 内单文档）。
- **计算预算**：每项变更固定 1e19 FLOPs（小模型 8 层 × 512 宽先行）；主结论在 300M 上用 1e20 FLOPs 复现。"训练步数相同不等于计算相同"——报告参数量与 FLOPs，禁止用扩大模型冒充组件收益。
- **优化设置**：同 AdamW 配方、bf16、按 token 数对齐 batch、同随机种子（mask 随机量对齐）；关键结果用多个随机种子或配对统计区间；模型选择集与最终测试集分开。
- **评测协议**（先写协议再跑实验，禁止结果出来后再改标准）：
  - **任务质量**：中文分类（CLUE：TNEWS/IFLYTEK/CMNLI）、中文抽取（CLUENER + 4.4 断句标点）、中文检索（C-MTEB 检索子集 Recall/nDCG）、重排（C-MTEB Reranking）；
  - **长程证据利用**：合成探针——关键证据句放在距答案 0/2K/4K/8K token 处，测"证据距离—准确率"曲线（8K 目标最直接的检验）；
  - **原能力保留**：其余任务无显著下降（bootstrap 95% CI）；中英文分别报告；噪声稳健性（对输入扰动）；
  - **部署成本**：训练 FLOPs、8K 前向 FLOPs、8K 显存、同硬件下的延迟与吞吐、必要时索引体积。

### 3.2 判定协议与"只降 MLM 损失"的处理

**保留规则**：一项变更被采纳当且仅当 (1) 至少一类目标任务显著提升（bootstrap CI 不交叠）且 (2) 其余任务无显著下降且 (3) 单位吞吐成本增量 < 20%。

**"只降 MLM 损失、不改善应用表现"的变更——不保留。**处理方式：

- 从默认配置剔除，进入"观察清单"并记录原因假设（评测噪声 / 数据量不足以放大差异 / 能力与任务不匹配）；
- 复活条件：3 倍数据量或主模型规模复现出应用差异，或出现新任务证据（如长程探针 8K 尾部变好）；
- 依据：MLM 损失是代理指标；题目 Notes 明确"减少 MLM 损失但不改善目标任务的变化，不会仅凭'更新'被保留"。提高一个任务却显著伤害另一个任务时，按使用权重取舍或分支部署，不隐藏退化。

### 3.3 三项验证的预期与"什么结果会推翻预期"

| 变化 | 初步预期 | 推翻预期的观察 |
|---|---|---|
| V1 全局层 1/3、窗口 128 | 1/3 是 8K 成本/质量甜点；窗口 256 提升长程探针但增加 FLOPs | 1/4 或 1/6 在长程探针不降反升 → 减少全局层；窗口 64 即达长程饱和 → 缩小窗口；长程探针对任何配置都不敏感 → 8K 目标本身需要重新审视数据（没有远程证据的样本练不出远程能力） |
| V2 目标组合 | 片段恢复显著提升长程探针（4K 以后），RTD 线在分类/抽取上略优但成本更高 | 片段恢复只改善 MLM/span 损失而长程探针不动 → 按 §3.2 剔除；RTD 出现词频/局部流畅度捷径（判别过易）→ 弃 RTD |
| V3 词表 64K | 64K 效率甜点；96K 的 PPL 优势不转化为下游优势 | 48K 下游无显著劣化 → 选 48K 省参数 |

## 4. 小规模验证实验（真实运行，方法学演示）

> 目标不是证明 300M 设计正确（算力不允许），而是**把 §3 的"双指标判定协议"真实跑一遍**：固定数据与计算预算，比较微型编码器的四个架构变体，用"MLM 验证损失"与"4.4 断句标点 macro-F1"两个指标对照，检验"代理指标与任务指标是否一致"。实验配置、代码与完整结果见 `4_5/mini_ablation.py`、`4_5/results/`，结论见 `4_5/实验结果.md`。

| 项 | 设置 |
|---|---|
| 模型 | 自实现微型编码器：4 层 × 256 宽、8 头、序列 128，约 5M 参数 |
| 变体 | BASE（绝对位置+全注意力+GELU-FFN+LayerNorm）/ ROPE（换 RoPE）/ GEGLU（+GeGLU+RMSNorm+去偏置）/ LOCAL（+局部窗口 64+末层全局） |
| 预训练 | 人民日报 9801 语料 200 万字符，动态 MLM 30%，每变体固定 3000 步 × batch 128 |
| 探针 | 冻结编码器 + 线性 head，4.4 断句标点，300 步，macro-F1 |
| 硬件 | RTX 3050 Laptop 4GB（WSL2 + CUDA），与 4.4 同一环境 |
| 已知局限 | 同域数据（4.4 语料）既是预训练也是探针数据——这是方法学演示的故意简化，结论不能外推；已如实标注 |

（实验结果与按 §3.2 协议的解读见 `4_5/实验结果.md`：各变体 MLM 验证损失 vs 探针 F1 对比表与图；若出现"MLM 更优但任务更差"的实例，按 §3.2 协议给出处理示范。）

## 5. 自评与开放问题

- 可一句话检验的核心主张：**"8K 中英编码器的成本结构由注意力可见范围决定；训练目标由长程证据探针裁决；词表由下游效率而非 PPL 裁决；每一项保留都必须能被 §3.2 的协议否定。"**
- 与题目 Notes 的分歧点：验证三项的选择顺序（§3.1 已说明预算序逻辑）；训练起点（§1.5 把 Notes 的"优先继续适配"落实为前置检查后的首选路线）。
- 证据缺口（诚实声明）：默认配置依赖 ModernBERT 等单一证据源，其消融本身在小模型/小预算上完成；8K 中文长程探针为自建合成数据，存在生态位偏误；§4 实验是方法学演示，不能外推到 300M——所有结论按 §3.2 等待更大预算验证。
