- **P123**：固定 1,048,576 个训练窗口（每窗 64 token，共 67.1M token = 相同 6ND 主项 FLOPs）扫 9 种配方，最终验证困惑度从 88.29 到 238.85 相差 2.7 倍，学习率是差异主体；批量翻倍+步数减半不等于结果不变。入门问逐条列出 Transformer 论文的配方（BPE 37k、~25k token/批量、Adam β=0.9/0.98、4000 步 warmup + step^-0.5 衰减、dropout/标签平滑 0.1 等）。
- **P140**：先复核课件算例（s=4096→1/6、s=32768→4/3，与幻灯片一致），再按 jev 类公开特征（TypeSafe Jev、开源对照 StartLux-Decision：MoE 35B-A3B、flash-linear-attention、双向注意力、单问题多并行、RLCD）把公式逐项改写为 F ≈ 6·N_active·D + 12·L·D·d·m + 输出头小项 + Q·U·(2G+6)·N_active·s，手算账本：s=2048/8192/32768 时方阵配对项占参数项 0.094/0.374/1.497，线性注意力固定 0.140（且 s<d 时反而更贵）；RLCD 仅占预训练主项 1.5%；部署侧每问题约为 7B LLM 的 1/20。

## P115：如果一种改进减少了计算量，运行却没有变快，下一步应该测量什么

- 实验：L=6/d=512/h=8 手写注意力块栈，固定 B·s=4096 的 5 形状 × 3 实现（MHA 完整方阵 / MHA 因果掩码 / GQA4），外加同因果数学量三内核（math/efficient/flash）SDPA 对照。
- 核心数据（墙钟 ms，执行口径 TFLOPS）：s=128→2048 时 MHA_full 61.5→166.1ms；MHA_causal 66.4→220.6ms（数学 FLOPs 减半却慢 8–33%）；GQA4 56.7→183.7ms（执行 FLOPs 少 7–12%，墙钟 ±10% 无收益）。SDPA（s=2048）：math 只掩码 24.1ms / flash 真跳过 1.09ms = **22 倍**。
- 硬件上限实测：GEMM 峰值 fp32 3.24、fp16 9.24 TFLOPS；带宽 183GB/s；ridge 17.7 FLOP/byte。利用率采样 90–98% 但有效 TFLOPS 仅 0.7–2.9——利用率 ≠ 效率。
- 测量清单（答案本体）：① profiler 时间分解（834 算子/迭代；CPU 发射 59/136ms < CUDA 85/182ms，发射不是瓶颈；triu 掩码每次迭代在设备上重建）② 执行口径 FLOPs 与有效 TFLOPS ③ 算术强度 vs 实测 roofline ④ 利用率与功耗 ⑤ 内核后端可用性（flash 仅 fp16）⑥ 形状与批量扫描 ⑦ 数据传输复测。
- 两次测量异常的诚实记录：copy 512MB 首测 6.2GB/s → 复测 183.2GB/s（瞬时环境干扰，本机 WSL2 与 Windows 共享 GPU）；B=32 批量尖峰 1357/1469ms 连续两次复现 → 新进程重测 314–400ms（形状循环后的分配器状态伪瓶颈）。结论：单次测量会撒谎，必须同环境复测。

## P123：同样 FLOPs 时，训练配方的影响有多大

- 入门问：配方 = 数据与预处理 / 训练目标 / 批量与训练长度 / 优化器 / 学习率日程 / 正则化 / 初始化与数值设置 / 检查点选择。Transformer 论文：WMT2014、BPE ~37k 词表、~25k+25k token 批量、Adam β₁=0.9 β₂=0.98 ε=1e-9、4000 步 warmup + step^(−0.5) 衰减、dropout 0.1、标签平滑 0.1、大模型最后 20 检查点平均。
- 实测：人民日报 1998 语料字符级 MiniGPT（d=64/L=2/h=4，词表 4566），固定总训练窗口 B×steps = 1,048,576（= 67.1M token = 相同 6ND FLOPs），9 种配方单变量对比（无发散；B=1024 时词表头 logits ≈1.2GB 超 4GB 显存，改为分块词表头 + 块级梯度重计算，全部配方同一代码路径）：

| 配方（其余同基线） | 改动 | 验证困惑度 |
|---|---|---|
| R1 基线 | B=512, lr=3e-3, cosine, warmup=102, dropout=0.1 | 115.23 |
| R2 lr 小 10 倍 | lr=3e-4 | 238.85 |
| R3 lr 大 10 倍 | lr=3e-2 | **88.29** |
| R4 批量翻倍 | B=1024, steps=1024 | 130.45 |
| R5 批量翻倍+lr√2 | B=1024, lr=3e-3·√2 | 117.80 |
| R6 无 dropout | dropout=0 | 114.38 |
| R7 标签平滑 | 0.1 | 115.68 |
| R8 常数 lr | schedule=constant | 101.55 |
| R9 长 warmup | warmup=50% 步数 | 114.84 |

- 继续追问（批量翻倍、更新次数减半）：不一定相同。梯度噪声与泛化、学习率日程失配（warmup 比例、每个 token 被更新的次数）、优化器状态与步数耦合都不随 token 数不变而保持。实测：R4 vs R1 = 130.45 对 115.23（同 lr 劣化 13.2%）；R5 vs R4 = 117.80 对 130.45（lr√2 只补偿约一半，仍比 R1 差 2.2%）。

## P140：对 "jev" 类 System One 决策模型，公式需要做哪些修改

- 公式复核：L=32/d=4096/D=1e12 时 s=4096 注意力项/参数项 = 0.1667（=1/6）、s=32768 = 1.3333（=4/3），解析式 s/(6d)，与幻灯片一致。
- 调研口径：Jev（TypeSafe，2026-09-15）：不做文本生成，输入程序状态 + 预定义问题 → 类型化决策（Choice/Score/Noul，带校准概率），RLCD 训练，70–500ms，$0.042/M 输入 token。开源对照 StartLux-Decision：MoE 35B-A3B、flash-linear-attention + causal-conv1d、Instant 双向注意力、单次前向多问题并行（字母位置读出）、256K 长状态分块、BF16/Q8_0 鲁棒、RLCD²/AutoThink。
- 逐项修改：① 6N_block·D → 6·N_active·D（MoE 激活参数，35B-A3B 下约为同参数稠密的 3/35）② s² 项 → 线性注意力 12·L·D·d·m，与 s 无关（m=d 时 = 方阵项固定在 s=d 的值；s<d 时反而更贵，方向性！）③ GQA 不改变 s² 配对项（课件 GQA 页明文），只缩 K/V 投影（N_block：12d²→10.25d²）与 KV 缓存（1/8）④ 双向注意力不减半，换 K 问题并行摊薄 ⑤ 词表头消失 → 有界输出头（小 4 个数量级）⑥ 加 RLCD 采样项 Q·U·(2G+6)·N_active·s，无思维链使 s 不含 t_think。
- 手算账本：S1（L=16/d=3072/E=16/k=2/D=0.5T）：N_total≈6.4B、N_active≈2.15B；方阵配对项占比 s=2048→0.094、8192→0.374、32768→1.497，线性 0.140；S2 RLCD（G=8/U=4/Q=1e6/s=512）≈9.7e19 = 预训练主项 1.5%，带 2000 token CoT 放大 4.9 倍（s=128/t=8000 时 63.5 倍）；S3 部署每问题 ≈ 7B LLM 的 1/20——与"输出免费、输入计价"同向。

## 结论与局限

- P115：速度由"执行口径 × 实现效率 × 瓶颈位置"决定，数学 FLOPs 只给下限；改进必须打在实测瓶颈处（flash vs math 的 22 倍是最直接的证据）。
- P123：相同 6ND FLOPs（= 同总 token）下 9 种配方最终验证困惑度相差 2.7 倍（88.29–238.85），学习率是差异主体，批量×日程交互次之，dropout/标签平滑/warmup 在 ±1%。批量翻倍+步数减半（同 lr）劣化 13.2%，lr√2 只补偿约一半——"运算账"相同不保证"优化账"相同。
- P140：System One 把"每 token 全部参数"与"每个位置全部配对"都打破了——6ND 主项改用激活参数，s² 项被线性注意力消掉，但 RL 采样与摊销必须显式入账；6ND 的 ND 结构不变，变的是每一项的系数与变量。
- 局限：4GB 笔记本卡 + WSL2 的测量值带本机特征（GEMM 峰值仅为规格值的 ~37%，与 Windows 桌面共享显存，B=1024 需分块词表头 + 梯度重计算才放得下——绕行已如实写入报告）；P123 是 67.1M token 预算的微型字符模型，方法学演示不外推规模；jev 无公开论文，架构数字为示意算例。所有数字来自真实运行，异常与绕行如实披露。
