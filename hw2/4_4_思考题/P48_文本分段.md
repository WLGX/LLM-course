课件以 Brown 语料为例：只把句号当分隔符，只有 93.20% 的句子会被正确识别（句号还用于缩写、小数点等），因此句子分段是一个有歧义的问题。思考题要求：

## 一、为什么文本分段很重要（提示：RAG）

分段（句子分段是其中一层）几乎是所有下游任务的**第一步**：课件 NOTES 里就说，翻译程序的第一步就是切句；语音识别也要先确定"哪里是一句"。分句质量会**逐层传导**到分词、句法、检索与生成。

在 RAG 场景下它更重要，因为**检索的单元是 chunk 而不是整篇文档**：

- 向量库是按 chunk 建索引的。如果句子边界错了，一个完整事实会被劈成两半，召回到的只有半截上下文，生成答案自然残缺；反过来块太大，一个 chunk 里塞进多个无关主题，噪声拉低相似度、浪费上下文 token。工程界常说"切分是 RAG 投入产出比最高的调优点之一"（[腾讯云工程对比](https://cloud.tencent.com/developer/article/2729832?frompage=seopage)、[CSDN RAG 切分策略对比](https://blog.csdn.net/ajhddjangc/article/details/165848566)）。
- 长文档整体向量化会稀释语义（一整篇文档的 embedding 变成一个"平均脸"），相似度匹配精度大幅下降；因此必须先在句子/段落边界处切成小块（[CSDN RAG 全链路](https://blog.csdn.net/yonggeit/article/details/169129854)）。
- 主流做法是"先分句、再分块"：递归切分（RecursiveCharacterTextSplitter）按"段落 → 换行 → 句号（。！？/ .!?）→ 空格 → 字符"逐级降级找边界，句子分段正是这套规则的最关键一层（[CSDN 递归切分最佳实践](https://blog.csdn.net/Z987421/article/details/169158407)、[Runoob RAG 指南](https://www.runoob.com/ai-agent/retrieval-augmented-generation.html)）。实践中句子分段器（如 PySBD / LTP）经常被直接用作 chunker 的前置步骤。

所以"分段"不只是 NLP 课堂练习：它决定 RAG 检索召回的下限。

## 二、如何进行文本分段：规则 vs 学习

分句本质是**判断每个标点/字符是不是句边界**，难点在排除"假阳性"。

**规则方法**：维护缩写表（Mr./Dr./U.S.）、小数点、引号配对等规则。代表是 **PySBD**（[GitHub/PyPI](https://pypi.org/project/pysbd/)），它把英文 SBD 的 Golden Rules 规则集工程化，支持 20+ 语言。优点是快、零依赖、可解释；缺点是规则要手工维护，跨领域（法律、生物医学）会退化（[PySBD 论文解读](https://zhuanlan.zhihu.com/p/359957190)）。

**无监督统计方法**：NLTK **Punkt** 用搭配检测自动发现缩写，不依赖人工规则表，但据评测对括号、列表项、混合大小写文本较吃力（[PySBD 评测](https://zhuanlan.zhihu.com/p/359957190)）。

**监督学习方法**：把分句做成序列标注（每个 token 二分类：句边界/非边界）。经典路线 BiLSTM-CRF，现在多用 BERT 类模型微调。监督模型更擅长利用上下文，但依赖标注数据，且域外泛化可能不如规则（stanza 在生物医学文本上就曾被报告过这个问题，[同上](https://zhuanlan.zhihu.com/p/359957190)）。领域内效果最好的做法是对领域语料微调（如法律文本 SBD，[arXiv:2504.04131](https://arxiv.org/html/2504.04131v1)，该文里 pySBD 的 F1 仍与监督模型在同一量级）。

**演示实验 A（真实运行）**：我构造了 5 句含缩写/小数/引号/价格的英文，朴素"按句号切" 5 例全错（把 Dr./p.m./$19.99 里的句号都当句尾），PySBD 5 例全对——这就是课件 93.20% 的"歧义"来源。日志见 `results/seg_demo_log.txt`。

**中文的特殊性**：中文句末标点（。！？…）相对规整，没有"缩写用句号"的惯例，所以**规则分句在规范文本上几乎无损**。演示实验 B：把人民日报 1998 原始语料前 3000 行拼成 37.9 万字符的"无换行纯文本流"，文本中 4733 个句末标点，规则切出 4695 句（少量出入来自无标点标题行与引号内标点），平均句长 48 字符。但规则在三个地方会翻车（实验 B2 实测）：引号嵌套（'你好。'里面的句号被当句尾）、句中省略号、以及网文"一句一段"——没有标点、靠换行分句，纯标点规则完全看不到边界。这正是课件提示"关键在于能接受多大的窗口、网文对话一句一段"的含义：**分句器必须把换行当作边界信号**，而不只是标点。

## 三、当前最受好评的模型（中文 / 英文）

综合检索到的评测与工程实践（[GitHub topic: sentence-boundary-detection](https://github.com/topics/sentence-boundary-detection?o=desc&s=stars)、[OCR 与句子分割调研](https://zhuanlan.zhihu.com/p/17914757968)）：

| 语言 | 推荐 | 类型 | 说明 |
|---|---|---|---|
| 英文（通用） | **PySBD** | 规则 | Golden Rules 规则集，快、准、多语言，通用文本事实标准（[PyPI](https://pypi.org/project/pysbd/)） |
| 英文（神经 SOTA） | **wtpsplit SaT** | 自监督神经 | ACL 2023 "Where's the Point?"，85 种语言、**标点无关**（能切语音转录/社交媒体等无标点文本）、支持长度约束与 ONNX 加速（[项目页](https://github.com/segment-any-text/wtpsplit)、[SaT 模型演进](https://blog.csdn.net/gitblog_00635/article/details/151916123)） |
| 英文（领域） | 领域微调 BERT 序列标注 | 监督 | 法律/生物医学等专业文本微调后优于通用模型（[arXiv:2504.04131](https://arxiv.org/html/2504.04131v1)） |
| 英文（轻量备选） | NLTK Punkt / spaCy sentencizer | 无监督/规则 | 已有 nltk 或 spaCy 管线时顺手可用，速度极快 |
| 中文（推荐） | **哈工大 LTP** `sent_split` | 监督（ELECTRA） | 中文开源里最常用的分句器，分句+分词+词性一条龙（[LTP 分句用法](https://m.blog.csdn.net/pippinxu/article/details/143405123)） |
| 中文（备选） | **HanLP 2.1** | 规则+多语种分句模型 | `split_sentence` / 多语种分句模型（[libraries.io](https://libraries.io/pypi/hanlp)） |
| 中文（规则/轻量） | 自写规则（。！？…+引号配对+换行） | 规则 | 新闻等规范文本几乎无损（本实验 B 实测）；网文需加换行边界 |
| 中文（无标点） | wtpsplit（含中文） | 神经 | 语音转录等无标点中文场景（[wtpsplit 85 语言](https://m.blog.csdn.net/gitblog_00172/article/details/152535648)） |

一句结论：**规范文本用规则（英 PySBD / 中 LTP 或规则）；无标点、多语种、社交媒体用 wtpsplit SaT；专业领域自己微调**。jieba 只有分词没有分句，不能用于本题。

## 四、自己写一个分段模型：窗口问题

把分句形式化为**字符级二分类**：对文本中每个位置，预测"这里是不是句边界"。管线四步：

1. **特征**：目标字符前后 k 字符窗口 + 标点/引号/换行指示特征；
2. **标签**：边界位置为 1，其余为 0；
3. **模型**：LogisticRegression（玩具）→ BiLSTM-CRF → 预训练 BERT 加分类头（真实系统）；
4. **解码**：预测为边界的字符处切开。

**窗口大小的权衡**（课件问题的关键）：
- 判断"这个句号是不是句尾"往往要看**几字符到几十字符**的上下文（缩写 vs 句尾、引号是否闭合）。新闻长句需要较长窗口；BERT 类模型的 512 token 窗口对绝大多数句子足够，超长段落用滑窗 + 重叠区合并边界即可。
- 网文对话"一句一段"恰恰是**窗口几乎无用的极端**：边界信息在换行符里，而不是上下文里。所以特征里必须显式编码换行；否则模型看到的是没有标点的一段话，学不到任何东西。
- 反过来，语音转录没有标点也没有换行，需要模型有**更长视野**去学"停顿时长/语义完整度"，这正是 wtpsplit 标点无关训练要解决的问题。

**演示实验 C（真实运行）**：我用 5 字符窗口特征 + sklearn LogisticRegression，在人民日报前 2400 行（约 29.3 万字符）上训练、后 600 行（约 7.3 万字符）上测试，句边界 F1 = 0.996。诚实说明：标签是用规则自动生成的（弱监督），所以它学到的就是规则逻辑，新闻文本上两者等价——模型的价值要到规则失效的领域（B2 那类文本）才显现，而这需要相应领域的标注数据。

## 五、数据加工策略：如何准备分段数据集

"数据加工比模型麻烦"完全同意，几个可操作的方案：

1. **弱监督自动造标签（成本最低）**：用带标点的大规模文本（新闻、书籍），把句末标点位置自动标成边界——本实验 C 就是这条路。陷阱：自动标签继承了规则的错误（引号内句号、省略号），训练出的模型上限就是规则。
2. **模型预标注 + 人工抽检纠错（性价比最高）**：先用 PySBD/LTP 标注，人工只纠错边界样本（引号嵌套、缩略语、对话），形成"难例集"反复迭代——标注量小一个数量级。
3. **全人工标注（最贵但目标最干净）**：课件 NOTES 提醒了一个关键点：**标注决定了目标**——如果你标的是"语义群/句组"，模型学到的就是按语义群切，而不是按语法句切。所以先想清楚下游要什么粒度（RAG chunk 要语义完整段，翻译要完整句），再定标注规范。
4. **无标点语料（语音转录、OCR）**：先跑一个标点恢复模型（punctuation restoration）再加回标点，或者直接用 wtpsplit 这类标点无关模型；人工标注这类数据最费，优先找现成数据集。
