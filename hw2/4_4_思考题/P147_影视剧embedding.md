# hw2 思考题 · P147 影视剧 embedding（L2 part1 第 147 张）

## 题目

电影推荐系统处理四类要素：影视剧（《阿甘正传》《星际穿越》…）、演员（汤姆·汉克斯…）、导演（斯皮尔伯格、诺兰…）、类型（Sci-Fi、Drama…），以及观影记录（用户 ID + 观看的电影序列）。思考题：

1. 使用什么模型，可以给定目标电影，预测相关电影？（因为用户 A 看了这部电影，所以推荐其他电影）
2. 用户喜欢汤姆·汉克斯，是否就只能推荐汤姆·汉克斯主演的其他电影？
3. 电影分类只能是预置的、一般意义上的 Genre 吗？
4. 还有哪些计算可能？数据上还需要什么？**最关键的：新电影、新演员出现时会发生什么？**

本回答配套运行材料：`scripts/movie_embedding_demo.py`（item2vec 玩具实验，合成数据，明确标注），结果见 `results/movie_embedding_demo.json` 与 `.log`。

## 一、用什么模型：观影序列上的 word2vec（item2vec）

这和本课刚学的 word2vec **完全同构**：把"用户观影序列"当语料、把"电影"当词。

| word2vec | 电影推荐 |
|---|---|
| 语料：句子序列 | 语料：每个用户的观影序列 |
| 词 | 电影（item） |
| 上下文窗口 | 同一序列里相邻观看的电影 |
| 训练目标（SGNS） | 最大化"共现电影"的条件概率 |
| 词相似度 | 电影相似度 → 相关电影推荐 |

这就是 2016 年微软提出的 **item2vec / prod2vec**（Barkan & Koenigstein, *Item2Vec: Neural Item Embedding for Collaborative Filtering*, IEEE MLSP 2016）：用 word2vec 在 item 序列上训练，把 item 映射到低维向量，余弦相似度即"相关电影"。

**演示实验（真实运行，合成数据）**：我构造了 49 部带导演/类型/主演标签的电影 + 3000 个合成用户的观影序列（导演粉/演员粉/类型粉/混合四类偏好），gensim Word2Vec(sg=1, window=5) 训练后直接检索：

- 《星际穿越》→ 盗梦空间(0.55)、记忆碎片(0.40)、头号玩家(0.38)、敦刻尔克(0.38)、蝙蝠侠：黑暗骑士(0.36)——**诺兰导演簇**被完整学出来了；
- 《阿甘正传》→ 猫鼠游戏(0.51)、费城故事(0.43)、拯救大兵瑞恩(0.37)——**汤姆·汉克斯主演簇**；
- 《华尔街之狼》→ 无间道风云(0.66)、禁闭岛(0.55)、猫鼠游戏(0.54)、好家伙(0.53)——**斯科塞斯 + 小李**的混合簇；
- 定量检验：top10 近邻中同导演占比 0.178（随机基线 0.057，约 3.1 倍）、同类型 0.506（基线 0.131，约 3.9 倍）、共享主演 0.171（基线 0.061，约 2.8 倍）。

工业上这个思路的扩展就是**双塔（two-tower）召回**：用户塔（把该用户的观影序列平均/序列编码成向量）+ 物品塔（电影向量），用内积/余弦做召回，再用精排模型排序。

## 二、喜欢汤姆·汉克斯 ≠ 只能推汉克斯的电影

不需要，而且通常不应该。**共现才是 embedding 的老师，不是某个单一属性**。演示实验里《阿甘正传》的近邻里确实有汉克斯的《猫鼠游戏》《费城故事》，但《华尔街之狼》的近邻里既有斯科塞斯的《好家伙》也有小李的《禁闭岛》《无间道风云》——向量把"导演、类型、演员"多个维度的共现信息**叠加编码**在同一空间里，近邻检索天然地跨维度混合。

所以"喜欢汉克斯"这个信号在向量空间里会自动延伸出三类推荐：

- 同一演员：费城故事、荒岛余生（协同过滤式的直接扩展）；
- 同一类型/题材：阿甘正传是"剧情/美国往事"型，同类型高分片也是候选；
- 同导演/同创作团队：泽米吉斯、斯皮尔伯格的其他电影。

工程上更明确的做法是**多路召回 + 精排**：user-to-item 双塔、item-to-item 相似度、演员/导演/类型的图嵌入（知识图谱 + TransE/图神经网络）、以及热门/新鲜度兜底，各路召回交给精排模型权衡。若只有"演员"一条规则，就退化成了基于内容的窄推荐，会把用户锁死在信息茧房里。

## 三、电影分类只能预置 Genre 吗？

不是，预置 Genre 是最弱的一档特征，至少有三种更丰富的"分类"：

1. **学出来的连续类别（embedding 本身）**：上面的实验已经说明，不需要人工打 Genre 标签，向量自己就学出了"诺兰簇""小李簇"——这是**无监督发现的细粒度类别**，粒度、维度都远超预置的 8 个 Genre。
2. **多标签 + 混合标签**：一部片同时是"科幻 + 悬疑 + 亲情"（星际穿越）；Genre 应该做成多热编码而不是单选。还可以加内容侧标签：年代、地区、奖项、节奏（慢/快）、适合人群。
3. **知识图谱里的类型**：Genre 只是实体属性之一；导演—演员—制片厂—系列（漫威宇宙）构成图结构，图嵌入（如 TransE/R-GCN）能把"系列""宇宙"这种预置表里没有的类别学出来。
4. **LLM/多模态内容编码**：海报、预告片、剧情简介经过视觉-文本编码器得到的向量本身就是"内容分类"，且**对新片可用**（见第四题）。

## 四、其他计算可能、还需要什么数据、以及冷启动

**还可以算什么**（除相似度检索外）：

- **向量算术**：类比推理——"导演风格"向量可以平移（星际穿越 − 诺兰风格 + 斯皮尔伯格风格 ≈ 头号玩家这类片），word2vec 的 king−man+woman 思想直接搬过来；
- **用户向量**：把用户序列里电影向量的均值（或 RNN/Transformer 序列编码）当用户向量，做 user→item 召回，而不是只做 item→item；
- **序列化推荐**：把"下一部看什么"当序列预测（GRU4Rec / SASRec / BERT4Rec 的思想），利用观看顺序信息；
- **图计算**：用户-电影二部图 + 知识图谱上的随机游走/图卷积（DeepWalk、PinSage 的思路）；
- **多任务**：预测"会不会看 + 会不会喜欢 + 看多久"三个目标联合训练，比单一相似度更贴近业务。

**还需要什么数据**：除观影序列外，最有价值的是 (a) 电影内容特征（简介、海报、预告、字幕、影评），(b) 用户反馈的强弱信号（点击/看完/评分/收藏，负样本——推荐了但没点），(c) 上下文（观看时间、设备、是否家庭共享账号）。只有正样本没有负样本是推荐系统最常见的坑。

**新电影、新演员来了会怎样（冷启动）——最关键的问题**：

- **纯协同/纯 item2vec 直接失效**：新电影没有任何观看记录 → 语料里没出现过 → 词表外（OOV），**没有向量**，无法做相似度检索。演示实验里我把《阿凡达》《荒岛余生》《信条》从训练集删掉，检索立刻 KeyError——这就是冷启动的本质：**模型只能推"见过的"东西**。
- 新演员同理：演员侧的共现统计里没有他，演员向量/知识图谱节点都不存在。
- **缓解办法（按成本排序）**：
  1. **内容特征初始化**：新片有导演/类型/主演/简介，用同导演+同类型已有电影向量的均值给新片一个"出生向量"。演示实验实测：《信条》用诺兰+科幻均值初始化后，近邻是盗梦空间(0.77)、星际穿越(0.67)——**直接站对了位置**；对照组（零向量=完全没有信息）近邻全是 0 相似度的随机电影。这正是"embedding 化"相对预置 Genre 表的优势：**内容特征和协同特征住在同一个空间里，可以混合初始化**。
  2. **少量在线数据快速更新**：新片上线后，用头几十条真实观看记录继续训练（word2vec 可以增量继续训练，或双塔模型每天全量/增量刷新），几天内向量就会收敛到正确位置；
  3. **多模态内容编码兜底**：LLM/视觉模型对简介和海报编码，天然支持新物品（零样本内容推荐）；
  4. **探索机制（exploitation-exploration）**：新片在排行榜/活动位强制曝光攒数据，用 bandit 算法分配流量；
  5. **知识图谱迁移**：新演员只要参演过任何一部已有电影，就能通过图上的边（出演—类型—合作者）获得初始表征，这叫 **graph-based cold start**。
- 反过来想，"来了新东西"恰恰是**序列化推荐 + 内容特征**相比"预置 Genre 表"的生存优势：预置表必须人工为每部新片打标签，而 embedding 方案只要有内容或少量行为就能自动接入。

**结论一句话**：题 1 用 item2vec/双塔召回；题 2 答案是不应该（向量天然跨维度）；题 3 答案是 embedding 自己就是更细的"分类"；题 4 的核心是——协同信号对**新物品天生失明**，必须用内容特征初始化 + 在线增量训练 + 探索流量来补。
