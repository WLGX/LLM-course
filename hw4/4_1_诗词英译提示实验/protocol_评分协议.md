# 评价协议（实验前预注册，2026-10-31，先于生成与评分执行）

本协议对应 L3 part1 第 89–90 张的要求："先写评价协议再跑实验""逐项核对期限、否定、例外、术语与格式"。
本文件在生成实验运行之前定稿；生成与评分脚本按本协议实现，结果不得反向修改协议。

## 1. 检查项（每篇诗词）

| 类别 | 对应课件措辞 | 本文操作定义 |
|---|---|---|
| time 时间/时序 | 期限 | 原文的时间先后、时态层次（当下/过去/未来/疑问时间）是否保留 |
| neg 否定 | 否定 | 原文否定结构（不/无/未/莫/难…）是否如实表达，未被改成肯定 |
| except 例外/转折 | 例外 | 转折、反预期、例外（却/竟/但/胜/少一人…）是否保留方向 |
| term 术语/文化词 | 术语 | 专名音译、节日/典故/意象是否保留，未替换成西方对应物；可用 notes 解释 |
| relation 关系 | 关系保持 | 主客体、条件因果、问答、视角、动作发出者是否与原文一致 |
| format 格式 | 格式 | 程序化检查，见第 3 节 |

关键语义单元在 corpus.json 中预定义（每篇 2–4 个，共 40 个），每个单元归入上述某一类别并附期望说明。

## 2. 单元评分（LLM 评审，盲评）

- 状态：`完整`(传达准确) / `部分`(只传达一部分) / `缺失`(未传达) / `错误`(明显曲解)。
- 每个单元必须给出 `evidence`：从译文中逐字引用的证据（与译文逐字一致，找不到可留空）。
- 量化：完整=1，部分=0.5，缺失=0，错误=0（缺失与错误同为 0，但在案例中分别报告）。
- 评审请求中**不出现**版本标识、模型名、提示文本；仅含原诗、单元列表、匿名译文。匿名编号到评分的映射在评分后恢复。
- 评审模型与生成模型相同（deepseek-chat），评审温度 0，独立调用；评审响应保留原文存档。

## 3. 格式检查（程序化，不依赖 LLM）

对每份译文输出：
1. 可解析为 JSON 且含 translation、notes 两键（notes 为数组）→ 否则 format_violation=“非法JSON/缺键”。
2. translation 行数 == 原诗行数 → 否则记“行数不一致”。
3. len(notes) ≤ 2，每条 ≤ 30 英文词，译文 ≤ 120 英文词 → 否则记“字数/条数超限”。
4. 不含题名与原文以外的诗句 → 记“增译原文没有的诗句”。
任一违规即 format_ok=0，并记录违规类型。

## 4. 整体可读性

- 评审同时给出 `overall`（1–5）：语法、流畅、诗意；与单元判定在同一次评审调用中输出。

## 5. 汇总与判定（先于结果声明）

- 每（诗 × 版本）取 2 次重复的均值；同诗配对差值：B−A、C−A。
- 单元层面：同一单元上 0→1 或 0.5→1 计**改对**；1→0.5 或 1→0 计**新增错误**（0.5 与 0 之间变化另列）。
- 成本：每版本 input/output token 总量、平均每次调用 token、重试次数（重试只允许 HTTP 错误、超时或非法 JSON，且计入成本；不得因译文质量重试）。
- 判定规则：若 A 在多数类别与整体可读性上不劣于 B/C，且 B/C 未带来稳定的单元级改善，则**最简提示胜出**；若某版本减少某类别错误但损害普通句子，则按类别分别报告，不做总体胜出声明。

## 6. 诚实性条款

- 保留全部原始输出（含失败调用）。
- 开发集 4 篇用于校准提示与协议；校准后协议冻结，正式测试集 12 篇只用于最终比较。
- 未参与修改的样本：候选锁定后，测试集所有样本均只评一次，不做挑选。

## 7. 事后补充说明（2026-10-31，运行完成后追加，不改动上述预注册条款）

- 运行中发现一处**设计瑕疵**：版本 C 的示例 2 原文（"遥知兄弟登高处，遍插茱萸少一人"）取自 test 集 T1《九月九日忆山东兄弟》第 3–4 句，因此 C 在 T1 上实际拥有该诗参考译文，与第 1 节"示例诗不在语料中"的声明不符（示例 1 无此问题）。
- 处理方式：主结论同时报告含 T1 与剔除 T1 两种口径；剔除 T1 后结论方向不变（B > A ≈ C），但 **T1 的 C 版本成绩不作为证据使用**。该瑕疵在报告第七节如实披露。
