# hw4 实验报告：唐诗宋词英译——简单提示、任务标准与边界示例的比较

> 对应课件 L3 part1 第 89–90 张。全部译文由真实模型调用产生，原始请求/响应逐条存档（`results/raw/`），评价协议在实验运行前定稿（`protocol_评分协议.md`）。

## 摘要

（dev 校准：24/24 生成成功、格式 100% 合规；单元均分 A=0.883、B=0.933、C=0.917，B/C 均改对 1 个术语单元且无新增错误。）test 集（12 首诗 × 3 版本 × 2 重复，共 72 次生成 + 72 次盲评）正式结果：单元均分 **B 0.980 > A 0.954 > C 0.947**（剔除 T1 后 B 0.978 > A 0.949 = C 0.949），B 相对 A 改对 3 个单元、0 新增错误；格式合规 B 23/24 > C 22/24 > A 20/24；整体可读性 A 4.12 > B 4.04 > C 3.92；B/C 的输入 token 约为 A 的 2.1/2.0 倍。**任务标准（B）以约 2 倍输入成本换得术语与例外类别的稳定改善，边界示例（C）不优于最简提示**；最简提示 A 未胜出，但与 B 的语义差距很小（0.954 vs 0.980）。

## 一、实验设计与预注册协议

- 版本 A：直接翻译（简单提示）。版本 B：在 A 的指令后加入五条任务标准（时间时序、否定例外、术语音译、关系保持、格式）。版本 C：不加任何规则陈述，只给两个边界示例（诊断性输入输出对，示例诗不在实验语料中）。
- 三个版本共用同一系统消息、同一模型（deepseek-chat）、同一采样配置（temperature=0.7, max_tokens=400）、同一输出格式要求（JSON，translation ≤120 词，notes 0–2 条每条 ≤30 词），每（诗 × 版本）重复 2 次。
- 语料分为 dev（4 首）与 test（12 首）。dev 集先跑，用于校准协议与观察提示是否符合预期；test 集结果作为锁定后的正式成绩，**候选锁定后不在 test 上做任何提示调整**。
- 评价协议（预注册，见 `protocol_评分协议.md`）：
  - 每首诗在语料中标注关键语义单元（category ∈ 时间/否定/例外/术语/关系 + 格式项），逐单元判定 完整(1)/部分(0.5)/缺失(0)/错误(0)。
  - 盲评：评审输入不含版本标识与模型信息；评审温度 0；每个判定必须附译文中逐字引用的 evidence。
  - 格式检查程序化完成：JSON 合法、译文行数与原诗行数一致、≤120 词、notes 数量与长度、译文不含题名。
  - 改对：相对 A，某单元均值从 <0.75 升到 ≥0.75；新增错误：从 ≥0.75 降到 <0.75；其余 ≥0.25 的变化记为部分变化。
  - 诚实条款：全部原始输出（含失败与重试）存档；重试仅限 HTTP 错误、超时或 JSON 解析失败，且计入成本；不重写任何模型输出。

## 三、三个提示版本（全文）

三个版本共用同一系统消息：

```
你是诗词翻译模型。你的任务是把用户给出的中文诗词翻译成英文。
你只能输出一个 JSON 对象，键为 translation（英文译文字符串，可在字符串内用 \n 分行）
与 notes（字符串数组，0 到 2 条，为英文读者理解所必需的背景注释，每条不超过 30 个英文单词）。
译文不超过 120 个英文单词，不含标题，只包含诗词译文本身。
不得输出 JSON 以外的任何内容。
```

用户消息（TAIL = "按系统要求以 JSON 输出。"）：

- **A 直接翻译**：`将下面这首中文诗词翻译成英文。\n\n{原诗}\n\n按系统要求以 JSON 输出。`
- **B 加入任务标准**：A 的指令之后、原诗之前插入五条标准（时间与时序；否定与例外；术语与文化词用拼音音译、节日器物典故保留意象可在 notes 解释；保持主客体、条件、因果与问答关系；格式行数一致、只译原文不增不删）。
- **C 只加入边界示例**：不加任何规则陈述，只给两个"原文→JSON 译文"示例（示例 1：春蚕到死丝方尽，蜡炬成灰泪始干；示例 2：遥知兄弟登高处，遍插茱萸少一人，译文对"茱萸"用 zhuyu 音译并在 notes 解释），然后要求"参照同样的处理方式"翻译目标诗。

三个版本完整原文见 `prompts.py`（版本 B 的 `CRITERIA` 五条、版本 C 的 `EXAMPLE_1/2` 输入输出对）。

## 四、运行设置与成本

- API：DeepSeek（OpenAI 兼容接口 `https://api.deepseek.com/chat/completions`）；模型 `deepseek-chat`；生成 temperature=0.7、max_tokens=400；盲评 temperature=0、max_tokens=2000。
- 每（诗 × 版本）重复 2 次：dev 24 次生成 + 24 次盲评；test 72 次生成 + 72 次盲评。
- 重试仅限 HTTP 错误/超时/JSON 解析失败（最多 3 次），重试计入成本。

## 六、译文案例分析

### 案例 1：T3《清明》——任务标准直接改对节日术语

- A/C 译文："A drizzling rain falls on **the Mourning Day**; The mourner's heart is breaking on his way.…" 评审对「清明」单元判部分，evidence 引 "Mourning Day"——把节日名替换成了西方化说法，语义漂移。
- B 译文："**Qingming days**, the rain falls thick and fast, On the road, wayfarers' hearts are broken.…" 评审判完整，evidence 引 "Qingming days"——标准 3（音译保留意象）起效，两次重复一致。
- 结论：这是"明确规则 → 稳定改对"的干净案例；C 的示例中没有节日类术语，未能受益。

### 案例 2：T8《声声慢》「却是」——转折词是易漏点

- A/C："The wild geese pass by—my heart is breaking, **for they are** old acquaintances from former days."——"却"的转折方向丢失（"for"成了因果解释）。
- B："The wild geese pass by, and my heart aches—**Yet they are** old acquaintances from former days."——标准 2（否定与例外如实表达）把转折补回，评审由部分升为完整（重复 2 为部分）。
- 结论：这类功能词的改善幅度有限（0.5→0.75，两次重复不一致），但方向明确。

### 案例 3：T2《登鹳雀楼》「千里目」——B 与 C 都改对，机理不同

- A："To see a thousand **miles** farther"（部分：把"里"换算成英里，丢失原意象）。
- B："To exhaust the view of a thousand **li**"（完整：标准 3 音译）；C："To see a thousand **li** away"（完整：示例带来的音译倾向，示例 1 的"only till death"句并未涉及"里"，属泛化或巧合）。
- 结论：B 的改善可归因于明确规则；C 的改善机理无法从示例内容解释，是唯一一处 C 的正向变化。

### 案例 4：C 的两处负面变化

- T3「杏花村」C 重复 1："A cowherd points to **a cot amid apricot flowers**"（部分：过度意译，丢失地名感），重复 2 恢复 "Apricot Bloom Village"。同诗 A 两次均为 "Apricot Flower Village"（完整）——**C 在无对应规则时引入了 A 没有的不稳定**。
- T1「茱萸…少一人」C："All wearing zhuyu, **one face missing from the sight**"——该句是示例 2 译文的**逐字复用**（示例 2 原文正是本诗 3–4 句，见第七节披露），评审对重复 1 判部分。它说明边界示例会被当作"成品句式"直接搬用，而不是被提炼成规则。

## 七、讨论

- **B 的收益集中在它明示规则的类别**（术语 +0.075、例外 +0.035），在模型本来就满分的类别（否定/时间/关系）无边际作用；这符合"标准只修复基线会犯的错"的预期。
- **C 没有产生规则级泛化**：唯一正向变化（T2 的 "li"）无法从示例内容解释；负向变化包括逐字搬用示例句式（T1）与过度意译（T3 杏花村）。两个示例覆盖的现象面太窄，不足以形成稳定策略。
- **成本**：B 的改善以 2.1× 输入 token 换得；若按次计费，每次调用约多付一倍输入费用。输出长度 B≈A、C 更短（79.5 vs 105.9），C 的"省字"并未换来质量。
- **最简提示没有胜出**：按协议第 5 节判定规则，A 在单元分与格式上劣于 B（改对 3、新增错误 0），故不做"最简提示胜出"声明；但 A 与 B 的语义差距不大（0.954 vs 0.980），若场景对格式无硬性要求、对成本敏感，A 仍是合理选择。
- **设计瑕疵披露（协议第 7 节追加）**：版本 C 的示例 2 原文取自 test 集 T1《九月九日忆山东兄弟》第 3–4 句，C 在 T1 上实际拥有参考译文，违反"示例诗不在语料中"的预注册声明（示例 1 无此问题）。处理：主结论同时报告含/不含 T1 两种口径——剔除 T1 后单元均分 B 0.978 > A 0.949 = C 0.949，**结论方向不变**；T1 的 C 成绩不作证据使用（上文中已注明）。
- **局限**：单模型（deepseek-chat）；每组合仅 2 次重复，估计方差大；评审与生成同一模型（LLM-as-judge 偏差，已通过盲评、逐字 evidence、温度 0 缓解但未消除）；版本间差异未做显著性检验；单元粒度较粗（0/0.5/1）。

## 八、结论

在 deepseek-chat 上、16 首唐诗宋词的英译任务中：**加入任务标准（B）以约 2.1× 输入 token 的成本，稳定改善了术语与例外类别的语义保持（改对 3、新增错误 0），并把格式违规从 4 次降到 1 次；只加边界示例（C）不优于最简提示（A）**（剔除示例泄漏的 T1 后 A=C=0.949），且可读性略降。最简提示未胜出，但与 B 差距有限。值得保留的改动：B 的标准 2（否定例外）、标准 3（术语音译）、标准 5（格式行数）——三项都对应了可观察的改善；示例驱动的方式在本任务上不值得保留，除非示例覆盖面足够大且目标现象在示例中有明确对照。
